# Per-test coverage collection (`atlas cov shim`, `atlas cov run`)

Per-test evidence — *which production symbols did **this one test** execute* —
is what atlas derives a feature's implementation surface from
(`atlas cov sync --per-test`, issue #104). This page is about producing it.

Nothing produces it by default. The Go runtime writes coverage counters once,
at process exit, so a whole `go test ./...` run yields a single profile in
which every test's execution is already merged together. Taking that apart
afterwards is impossible: the counter data does not record who incremented
what.

So atlas takes the suite apart *before* it runs.

| Verb                    | Purpose                                                            |
| ----------------------- | ------------------------------------------------------------------ |
| `atlas cov shim init`   | Write the generated `TestMain` into the packages you want collected. |
| `atlas cov run`         | Run the suite with collection armed and ingest the result.           |

---

## Quick start

```bash
atlas cov shim init --package ./...     # once, and commit the result
go get github.com/sosalejandro/atlas    # the shim is a library your tests import
atlas cov run -- go test ./...          # every time you want fresh evidence
```

The second command leaves the store with one `test_coverage` row per
(test, symbol executed) pair, which is exactly what `atlas audit` uses for
its dynamic feature-surface derivation.

---

## How it works

`atlas cov shim init` writes `atlas_shim_test.go` into each selected package:

```go
// Code generated by `atlas cov shim init`. DO NOT EDIT.
package billing

import (
	"testing"

	atlascov "github.com/sosalejandro/atlas/packages/coverage/shim"
)

func TestMain(m *testing.M) { atlascov.Run(m) }
```

`shim.Run` is inert unless the environment variable `ATLAS_COV_DIR` names an
output directory, so **committing this file does not change what `go test`
does**. `atlas cov run` sets it, and then the shim:

1. runs the suite one top-level test at a time (`-test.run=^TestName$`),
2. clears the coverage counters before each test
   (`runtime/coverage.ClearCounters`),
3. photographs them after it (`WriteCountersDir`),
4. writes the package's meta-data file once, and a report saying what it did.

`atlas cov run` then turns each snapshot into a coverprofile with
`go tool covdata textfmt`, resolves each test to its indexed symbol, and
ingests the lot.

Three details of the Go runtime shape that loop, and are worth knowing when
reading the code:

- **`-covermode=atomic` is mandatory.** The runtime refuses to clear counters
  in any other mode. `cov run` injects the flag; if you run the suite
  yourself without it, the shim degrades (see below) rather than recording
  counters it knows are shared.
- **The first `m.Run` initialises coverage.** Before it, meta-data cannot be
  written and counters cannot be cleared, so the shim opens with a warm-up
  run that matches no test.
- **Only top-level tests are separable.** A subtest — parallel or not —
  finishes inside its parent's run, so its execution is attributed to the
  parent. That is a real limit, and the right one: `t.Run` names are not
  symbols atlas indexes.

## What the flags do to your `go test` command

`cov run` adds three flags to a `go test` command that does not already carry
them, and prints the command it actually ran:

| Injected           | Why                                                                                        |
| ------------------ | ------------------------------------------------------------------------------------------ |
| `-covermode=atomic` | The only counter mode the runtime will clear.                                              |
| `-coverpkg=./...`   | Without it a test appears to execute only its own package, which makes the cross-package attribution the whole feature depends on impossible. Override with `--coverpkg`. |
| `-count=1`          | A cached test result runs no binary, and a binary that does not run writes no counters.    |

Any command that is not `go test` is run verbatim; pass the flags yourself.

## Parallel tests, and what "degraded" means

A package whose tests call `t.Parallel()` is collected **per package**, not
per test, and the degradation is reported:

```
cov run: go test -count=1 -covermode=atomic -coverpkg=./... ./...
  6 per-test profile(s) from 3 package(s), suite exit 0
  degraded (plan) example.com/repo/shipping: 2 of 2 tests call t.Parallel()
    (TestRate, TestZone); collecting them one at a time would take away the
    concurrency they asked for
```

The reasoning is worth being precise about, because the honest answer is not
the obvious one.

Parallel tests share one counter space, so a suite that runs them
concurrently cannot be photographed per test — a snapshot taken when one test
ends contains whatever the others did meanwhile. Atlas avoids that by running
one test per `m.Run`, which means a `t.Parallel()` test **can** in fact be
collected correctly: run alone, it owns the counter space, and its snapshot
is exactly its own execution.

What it loses is the concurrency. Serialising a suite that opted into
`t.Parallel()` is a change to how those tests run — anything they assert
about concurrent behaviour is no longer being tested, and a suite that
finished in a minute may not. Atlas will not make that trade silently, so the
default is to collect such a package whole and say so. Pass `--serialize` to
make the trade deliberately:

```bash
atlas cov run --serialize -- go test ./...
```

Degradation is **detected, never assumed**, and from two directions:

- **Statically, before the run** (`source: plan`): atlas parses each
  package's test files and looks for `t.Parallel()` in a test's own body.
  A call reached through a helper is not detected — and that miss is safe in
  the only direction it can fall: the package gets collected per test,
  serially, and the attribution is still exactly what ran.
- **At runtime** (`source: runtime`): the shim degrades a package when the
  counters turn out not to be clearable (`-covermode` is not atomic), when it
  cannot enumerate the package's tests, or when a clear fails mid-suite. In
  the last case the per-test snapshots already on disk are invalidated by the
  package's own report, and the cumulative counters — which are by then
  exactly the package total — are written instead.

A degraded package contributes a per-package profile and **no per-test rows**.
Wrong attribution is worse than coarse attribution: a feature surface derived
from evidence that says the wrong test ran the code is not recoverable by
anything downstream.

## Packages atlas will not touch

`cov shim init` skips, and reports:

- a package that **already declares `TestMain`**. Rewriting a suite's process
  entry point is not something a tool should do quietly. Opt in by hand:
  `func TestMain(m *testing.M) { atlascov.Run(m) }` — your existing setup and
  teardown can stay around the call.
- a package with **no test functions**, where a `TestMain` would only make the
  go tool build a test binary with nothing to run.

Re-running `shim init` is idempotent: unchanged files are not rewritten, and
a stale generated shim (ours, from an older atlas) is refreshed and reported
as `updated`.

## Overhead

Measured on this repo's benchmark fixture — 20 packages, 1,000 tests, 4,000
instrumented functions, Go 1.26, 12-core Linux box. The suite is deliberately
trivial (each test calls one function), which makes the shim's share of the
wall clock as large as it can be:

| Step                                        | Wall clock                     |
| ------------------------------------------- | ------------------------------ |
| `go test` with the coverage flags, shim off | 0.53 – 0.56 s                  |
| Same suite, shim armed (1,000 snapshots)    | 0.54 – 0.60 s (**+0 – 12 %**)  |
| `atlas cov run` end to end (suite + convert)| **≈ 15 s**                     |
| Counter data written                        | 4.2 MB (≈ 4 KB per test)       |

The shim itself is cheap: about 35 µs per test for the clear-and-snapshot
pair, which on any suite with real work in it disappears into the noise.

The end-to-end number is dominated by conversion, not by collection:
`go tool covdata textfmt` is one process per snapshot, ~14 ms each, and there
is no batch form of it that emits one profile per input. The conversions run
concurrently (one per CPU), which is what takes the 1,000-test fixture from
59 s to 15 s. If you only want the profiles and not the store write, pass
`--no-ingest`; if you want to keep the raw snapshots to convert yourself,
pass `--keep`.

## Flags

### `atlas cov shim init`

| Flag        | Default   | Description                                    |
| ----------- | --------- | ---------------------------------------------- |
| `--package` | `./...`   | Package patterns to write the shim into.       |

### `atlas cov run`

| Flag          | Default   | Description                                                                       |
| ------------- | --------- | --------------------------------------------------------------------------------- |
| `--package`   | `./...`   | Package patterns to analyse when planning collection.                             |
| `--coverpkg`  | `./...`   | `-coverpkg` value injected into a `go test` command that has none.                |
| `--out`       | (none)    | Also write the profiles here as `<test symbol>.out`, the layout `cov sync --per-test` reads. |
| `--work`      | (temp)    | Directory for counter snapshots. Implies `--keep`.                                |
| `--serialize` | off       | Collect `t.Parallel()` packages per test anyway, one test at a time.              |
| `--keep`      | off       | Keep the counter snapshots after the run.                                         |
| `--no-ingest` | off       | Collect and convert only; do not write to the store.                              |

## Collecting without `atlas cov run`

The shim needs nothing but an environment variable, so a CI job that already
has its own `go test` invocation can collect with it directly:

```bash
export ATLAS_COV_DIR=$PWD/.atlas/cov
go test -covermode=atomic -coverpkg=./... -count=1 ./...
```

Every package is then collected per test (there is no plan file to say
otherwise, so `t.Parallel()` packages are serialised without asking — the
`--serialize` behaviour). Point `atlas cov run --work "$ATLAS_COV_DIR"` at the
result to convert and ingest, or read the layout yourself:

```
<root>/meta/<import path>/covmeta.*             one per package
<root>/counters/<import path>/<TestName>/       one per test
<root>/counters/<import path>/_package/         a degraded package's single snapshot
<root>/reports/<import path>/shim.json          what that package actually did
```

The report is the authority on trust: a report whose `mode` is `per-package`
invalidates any per-test directories sitting next to it.

## Other languages

Go needs a shim because its runtime writes counters once. The other two
languages atlas indexes do not:

- **Python** — `coverage.py` has per-test contexts natively. Set
  `dynamic_context = test_function` in `.coveragerc`, run the suite, and
  `coverage json` emits one context per test. No shim; atlas has to learn to
  read contexts (not yet implemented — issue #128's remaining scope).
- **JS/TS** — per *test file* granularity from a vitest `onTestFinished` hook
  or a jest reporter that snapshots v8 coverage between files. Finer than the
  file is rarely worth the complexity; the file is usually the right unit.
  Also not yet implemented.
